# ETF 实时看盘

纯本地小工具,跟 `assistant-k8s/` 那套 K8s 部署完全独立——不需要集群,不需要 API Key,不进 Git 提交后自动部署的那套流程。

## 为什么不能直接监控 fund-monitor 里那 6 只场外基金

`assistant-k8s/fund-analyzer/analyze_fund.py` 里 `FUNDS` 监控的 6 只(000950/001594/001344/000248/015876/018103)都是**场外联接基金**——申购赎回按净值成交,净值每个交易日只在收盘后公布一次,没有"盘中实时价格"这回事,谈不上"看盘"。

这个工具改成监控它们各自对应的**交易所场内 ETF**(有真正的盘中逐笔成交和分时走势):

| 场外联接基金 | 场内 ETF | 跟踪指数(逐个核实过完全一致) |
|---|---|---|
| 000950 易方达沪深300非银ETF联接A | 512070 非银ETF(易方达) | 沪深300非银行金融指数 |
| 001594 天弘中证银行指数A | 515290 银行ETF(天弘) | 中证银行指数 |
| 001344 易方达沪深300医药ETF联接 | 512010 医药ETF(易方达) | 沪深300医药卫生指数 |
| 000248 汇添富中证主要消费ETF联接 | 159928 主要消费ETF(汇添富) | 中证主要消费指数 |
| 015876 富国中证消费电子主题ETF联接A | 561100 消费电子ETF(富国) | 中证消费电子主题指数 |
| 018103 易方达中证港股通消费主题ETF联接A | 513070 港股通消费ETF(易方达) | 中证港股通消费主题指数 |

另外加了几只不对应任何场外基金、纯粹是看盘需要的品种,排在卡片最前面(黄金优先,沪金主连排第一):

- **沪金主连(元/克)**,代码 `AUM`,上期所黄金期货主力连续合约——这才是银行 App 里那种"人民币实时金价"图对应的东西(跟国内现货金价 Au99.99 高度联动,只是期货合约,不是完全等价)。实时报价用新浪期货接口(`hq.sinajs.cn`,需要带 `Referer: https://finance.sina.com.cn`,新浪的股票接口也有这个限制)。
  分时图的数据来源比较特殊:新浪自己的"分时历史"接口(`stock2.finance.sina.com.cn`)实测**更新很慢/缓存很重**——午盘收盘到午后开盘之间只补了一条记录,之后盯了 15 分钟这条记录纹丝不动,同期反复查实时报价却是在正常跳动的。所以分时图改成 `server.py` 里一个**后台常驻线程**,每隔 60 秒(`FUTURES_POLL_SECONDS`)采一次实时报价,攒成一条线落盘存在 `dashboard/.futures-trend-cache.json`(已加进 `.gitignore`,不会进 git)。这个文件:
  - 内容带日期戳,每天第一次采样发现日期变了就自动清空重来,不会越攒越多产生一堆按日期命名的垃圾文件,固定就这一个文件。
  - 重启 `server.py` 会先从这个文件加载当天已经攒到的点,不会因为重启就清零丢数据。
  - 刚启动服务、又是新的一天时图是空的,要等第一个采样周期(最多60秒)才有第一个点,之后跟其他卡片一样慢慢长满。
  > 之前加过一版国际现货黄金(美元/盎司,代码 `XAU`,腾讯外盘行情 `hf_XAU`),前端每次刷新自己攒点、刷新页面就清空重来,体验不如现在这版服务端常驻攒点的方案,已经拿掉了。
- **518880 黄金ETF(华安)**——场内规模最大的黄金 ETF,经接口核实名称是"黄金ETF华安"。
- **516510 云计算ETF(易方达)**——"算力"目前没有对应的场内 ETF 产品:查过东方财富的基金全量列表,基金名称里没有"算力"二字;2023年有多家基金公司申报过算力/算力基础设施主题ETF,但没找到已上市、名称含"算力"的产品。云计算 ETF 是目前 A股市场里最接近"算力"主题、且真实存在的产品(重仓数据中心、云服务器等算力基础设施相关公司)。

改监控列表/顺序就编辑 `server.py` 里的 `INSTRUMENTS` 常量,展示顺序 = 列表书写顺序。默认 `kind` 是 A股场内 ETF(用东财+腾讯双源);`kind: "futures"` 是走新浪期货接口的品种(目前只有沪金主连)。

## 用法

```bash
cd dashboard
python3 server.py
# 浏览器打开 http://localhost:10000
```

展示每只 ETF 的最新价、涨跌幅、当日分时折线图。红涨绿跌(中国习惯,不是美股那套)。右上角显示最后更新时间、距下次刷新的倒计时,以及一个刷新间隔选择器(30秒/1分钟/5分钟/30分钟,默认30秒),选的值存在浏览器 `localStorage` 里,下次打开页面会记住。

## 作为常驻服务运行(launchd)

不想每次都手动 `python3 server.py`,可以注册成 Mac 用户级 LaunchAgent,登录/开机自动拉起,进程意外退出也会被 launchd 自动重启:

```bash
ln -sf "$(pwd)/dashboard/local.fund-dashboard.plist" ~/Library/LaunchAgents/local.fund-dashboard.plist
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/local.fund-dashboard.plist
```

`local.fund-dashboard.plist` 就在这个目录下,是"源文件",软链接到 `~/Library/LaunchAgents/` 只是为了让 launchd 能找到它——改完这个文件后不用重新做软链接,跑一下重启命令就生效。用的是 **系统自带的 `/usr/bin/python3`**,不是项目 `.venv` 里那个(launchd 起进程环境是干净的,不会激活任何 venv;`server.py` 本来也是纯标准库,压根不需要 venv)。日志在 `~/Library/Logs/fund-dashboard.log` / `fund-dashboard.err.log`。

改完 `server.py` 想让改动生效,或者怀疑它卡住了,用重启脚本(不在这个仓库里,是单独放的,因为跟"重启后台进程"这个操作本身相关,不是项目代码):

```bash
/Users/hliu/Software/script/restart-fund-dashboard.sh
```

真正要停掉(不想让 launchd 再管它)用 `launchctl bootout gui/$(id -u)/local.fund-dashboard`,单纯 `kill` 进程只会被 launchd 立刻重新拉起来。

## 数据来源和已知的坑

数据主用东方财富的公开行情接口(`push2.eastmoney.com` 实时报价 / `push2his.eastmoney.com` 分时数据),备用腾讯的公开行情接口(`qt.gtimg.cn` 实时报价 / `ifzq.gtimg.cn` 分时数据)。两个都免费、不需要注册 key,不提供任何可用性保证:

- 都**没有稳定的浏览器端 CORS 支持**,所以 `server.py` 在本地起一个小 HTTP 服务做转发——页面本身只跟 `localhost` 打交道,不存在跨域问题。
- 实测东方财富这个接口**会成串地抽风**(2026-08-21 调试和验收时都真实遇到过,6只 ETF 同时报 502,不是偶发的单次请求失败),纯靠重试解决不了根本问题。所以现在的策略是:东财失败后自动切到腾讯——两者是完全独立的两套行情基础设施,同时故障的概率远低于单边故障。哪只 ETF 实际是从腾讯拿到的数据,卡片名称旁会标一个"腾讯行情(东财故障切换)"的小标签,方便区分。
- 如果东财和腾讯**两边同时都失败**(理论上可能但目前没实际遇到过),对应卡片会显示"获取失败",下一次自动刷新(30秒后)会自己重试,不需要手动干预。
- 非交易时段打开,展示的是最近一个交易日收盘时的价格和分时数据,不会报错,但数据不是"实时"的。
